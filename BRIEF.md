# BRIEF — Чек-лист аудита amoCRM

Рабочее название: **«Аудит amoCRM от SolutionCRM»**. Папка и адрес: `amo-audit`.
Ссылка после публикации будет примерно такая: `https://<ваш-логин>.github.io/amo-audit/` (пример, точный адрес будет на шаге публикации).

## Задача одной фразой
Пройти по чек-листу, как настроена amoCRM, и за 10–15 минут получить оценку в процентах и понятный список, что исправить.

## Кто пользуется
- **Аналитики SolutionCRM**: проводят аудит у клиента на созвоне или сами, результат вставляют в отчёт или КП.
- **Клиенты**: открывают ссылку и проверяют свою amoCRM сами. Для них это ещё и лид-магнит: в конце видят, что не так, и кнопку «Обсудить с SolutionCRM».
- Открывают и с компьютера, и с телефона.

## Экраны

### 1. Старт
- Что это и сколько займёт времени (2–3 строки).
- Поле «Название компании» (необязательно, нужно только для заголовка результата).
- Кнопки: **«Начать аудит»**, **«Продолжить»** (если аудит уже начат на этом устройстве).

### 2. Чек-лист
- Пункты разбиты на блоки (состав ниже, это пример, а не окончательный список, его утвердим на следующем шаге):
  1. Воронки и этапы
  2. Карточка сделки и поля
  3. Задачи и дисциплина менеджеров
  4. Автоматизация (Salesbot, триггеры, Digital Pipeline)
  5. Каналы: телефония, мессенджеры, почта, формы сайта
  6. Аналитика и контроль (отчёты, дашборды, конверсии по этапам)
- Каждый пункт: короткий вопрос + подсказка «как проверить» (раскрывается по нажатию).
- Ответ на пункт тремя кнопками: **«Да» / «Частично» / «Нет»**.
- Сверху полоска прогресса: сколько пунктов пройдено.
- Кнопки: **«Назад» / «Дальше»** между блоками, **«Показать результат»**.

### 3. Результат
- Общая оценка в процентах и цветом: красный / жёлтый / зелёный.
- Оценка по каждому блоку.
- Список «Что исправить»: все пункты с ответом «Нет» и «Частично», сначала самые важные.
- Кнопки:
  - **«Скопировать результат»**: текст для отчёта, письма или мессенджера;
  - **«Обсудить с SolutionCRM»**: ссылка на ваш Telegram или сайт (какую ставить, уточним на шаге сборки);
  - **«Начать заново»**.

## Данные
- **Что вводим:** название компании (необязательно) и ответы Да / Частично / Нет.
- **Где хранится:** только в браузере на этом устройстве. Закрыли вкладку, открыли снова — ответы на месте. На сервер ничего не уходит, ни мы, ни кто-то ещё ответы клиента не видит.
- **Вопросы чек-листа** лежат в отдельном файле внутри приложения, чтобы их было легко дополнять без правки остального.
- Код открыт всем, поэтому в нём нет ключей, паролей и данных клиентов.

## Первая версия (что делаем)
1. Чек-лист из 6 блоков, примерно 30 пунктов, с подсказками «как проверить».
2. Ответы Да / Частично / Нет, прогресс, сохранение в браузере.
3. Результат: общий процент, проценты по блокам, список «Что исправить».
4. Кнопка «Скопировать результат» готовым текстом.
5. Удобно на телефоне и компьютере, в фирменном стиле SolutionCRM.

## Что НЕ делаем сейчас
- Вход по паролю и личные кабинеты.
- Отправку результатов нам (заявки, почта, Telegram): на GitHub Pages нет своего сервера.
- Подключение к amoCRM клиента и автопроверку настроек.
- Выгрузку в PDF (пока можно сохранить через «Печать → Сохранить как PDF» в браузере).
- Версию для Битрикс24.

## Готово, когда (проверяем руками)
1. Открываю ссылку на телефоне и на компьютере: всё читается, кнопки нажимаются пальцем, ничего не уезжает за край.
2. Отвечаю на половину пунктов, закрываю вкладку, открываю снова — ответы и прогресс на месте.
3. Отвечаю на всё: все «Да» дают 100 %, все «Нет» дают 0 %, в списке «Что исправить» ровно пункты с «Нет» и «Частично».
4. «Скопировать результат» → вставляю в Telegram, текст читается без лишних символов.
5. «Начать заново» очищает все ответы.

## Публикация
Приложение выложено в двух местах, оба обновляются сами из одного репозитория.
- **Vercel:** https://amo-audit-hzkf.vercel.app (тариф Hobby, команда «Solution», проект `amo-audit-hzkf`, выложено 13.11.2026).
- **GitHub Pages:** https://spartakkinzyabulatov-lgtm.github.io/amo-audit/
- Репозиторий (публичный): https://github.com/spartakkinzyabulatov-lgtm/amo-audit
- Обновить сайт: правим файлы в этой папке → `git add -A && git commit -m "…" && git push`. Vercel обновит сайт примерно за минуту, GitHub Pages — за 1–3 минуты. Не забыть поднять версию в `sw.js` (см. ниже).
- Превью: если отправить изменения в отдельную ветку (не `main`), Vercel сделает для неё отдельную ссылку-превью, основной сайт не меняется. Ссылка видна в Vercel → проект → Deployments (Выкладки).
- Ежедневное обновление данных (GitHub Actions) тоже коммитит в `main`, поэтому Vercel перевыкладывает сайт раз в день — это нормально.
- Тариф Hobby — только для личного некоммерческого. Сейчас это демо для обучения. Если начнём давать ссылку клиентам как лид-магнит SolutionCRM — нужен Pro (решает Спартак).
- Ключей у приложения нет. Если понадобятся — только в Vercel → Settings → Environment Variables (Настройки → Переменные окружения), не в код.

## Приложение на телефоне (PWA)
- Приложение ставится на телефон иконкой и открывается без интернета. За это отвечают `manifest.webmanifest` (название, цвета, иконки), `sw.js` (сохраняет файлы в телефоне) и папка `icons/` (исходник иконки — `icons/icon.svg`).
- **Правило: при КАЖДОЙ выкладке повышай номер версии в `sw.js`** — строка `var VERSION = "v1";` → `"v2"` → `"v3"` и т. д. Без этого телефон продолжит показывать старую сохранённую версию.
- Добавили новый файл в приложение (картинку, скрипт) — впиши его в список `CORE` в `sw.js`, иначе без интернета он не откроется.
- Установка: iPhone — Safari → «Поделиться» → «На экран „Домой“»; Android — Chrome → ⋮ → «Установить приложение» / «Добавить на главный экран».

## Данные, которые обновляются сами (блок «Полезное от SolutionCRM»)
- Источник: Google Таблица «amo-audit_полезное_v1» (Google Диск → «03 Маркетинг и продукты»), опубликована в интернете как CSV — её видят все, личного туда не писать.
- Колонки: `показывать` (да/нет) · `тип` · `заголовок` · `текст` · `ссылка`. Показывается до 12 строк с «да».
- `fetch.py` скачивает таблицу и пишет `data.json` (с датой обновления). Не ответила таблица — `data.json` не трогается.
- `.github/workflows/update.yml` запускает `fetch.py` каждый день в 07:17 по Екатеринбургу (02:17 UTC). Вручную: GitHub → Actions → «Обновить данные» → Run workflow.
- GitHub может запускать задание с опозданием на 5–15 минут. Если в репозитории 60 дней нет изменений, расписание выключится само — включается кнопкой Enable workflow в Actions.
